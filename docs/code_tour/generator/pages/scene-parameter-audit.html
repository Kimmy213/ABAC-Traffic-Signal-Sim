01Big picture

Menu ABAC > Verify Scene Against Code. It answers one question: does the scene still hold the values the code intends? The problem it guards against is described on the overview page. The scene saves every public field and overrides the code on load, and that once left a batch running on stale values.

02How it checks

A MonoBehaviour cannot be created with new, so the audit adds a throwaway copy of the component to a hidden object. That copy carries the code's defaults. Reflection then compares every public number and switch with the one in the scene. Because it walks every field rather than a list of known ones, the next drift is caught too.

It audits AdaptiveController, ScenarioManager and FixedController, the three whose numbers decide results. Lists and references are skipped. It allows five fields to differ on purpose: the debug switches, the panel switch and the logger's run labels.

Inside Unity

This menu item, on the open scene, with a dialog that says how to fix any drift.

Outside Unity

Tests/SceneAuditTest.cs reads SampleScene.unity as text in the test suite. It also checks values this audit skips, such as the scenario rates.

As of this build the scene agrees with the code on every audited field. This tour's variable tables run the same comparison over every component, and the only differences they show are per-lane spawner and zone settings that ABACSceneBuilder sets on purpose.
