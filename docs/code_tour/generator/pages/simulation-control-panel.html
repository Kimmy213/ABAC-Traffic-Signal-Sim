01Big picture

The on-screen control panel, and the way into a single run. It is what you use in a live demonstration: pick a test case, switch Fixed and Adaptive while the junction runs, speed time up, and watch every lane's queue and clock. It also starts and stops the batch.

  • Run: start, pause, resume, stop, restart, with a run state of Idle, Running, Paused or Finished.
  • Choose a test case, or run one built in the custom-case window.
  • Switch controller mid-run without clearing the road.
  • Show the lane table: signal, queue, oldest car, and SODA's queue clock.
  • Time a scripted case until the road is empty, and compare Fixed with Adaptive on it.

02Start-up

The test-case list is saved in the scene, and Awake builds it from code only when it is empty. The saved scene holds an empty list, so every Play starts with the current TestCasePresets. The Reload button exists for the case where it is not empty.

03Starting and ending a run

Seeds: a Poisson case uses randomSeed (12345 unless changed), so the same seed replays the same traffic; a scripted case uses the fixed 20260820. Scripted runs end themselves:

The clearance time is stored per controller for the selected case, and the panel prints which was faster and by how much. That makes a scripted case a quick head-to-head on identical cars.

04Switching controller mid-run

Both controllers are always stopped first; with both running, two groups could hold green at once. ScenarioManager.RunSingleExperiment uses the same three steps.

05The lane table: two different clocks

The table shows two waits per lane. They differ on purpose, and the difference explains how SODA decides:

  • Oldest car: ROIZone.GetLongestWaitTime, the real wait of the oldest car. Simulation ground truth; a tracker-free camera cannot know it.
  • Queue clock: now − queueStart of the lane's signal head, the number SODA's Q1 and Q2 actually use. It belongs to the lane, not to a car, and restarts each time the head is served.
