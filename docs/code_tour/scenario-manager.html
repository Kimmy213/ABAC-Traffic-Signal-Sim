ScenarioManager

Runs the experiment: 4 scenarios x 27 repetitions x 2 controllers = 216 runs, paired by seed.

01Big picture

The experiment itself. One press of Start batch run plays every scenario 27 times under each controller: 4 × 27 × 2 = 216 runs, about 11.5 hours at 10× speed. Each Fixed run and its Adaptive partner share a seed, so both face exactly the same cars and the difference between them is the controller alone.

  • Hold the batch settings and the four scenarios' arrival rates.
  • Run: for every scenario and repetition, a Fixed run and then an Adaptive run with the same seed.
  • Collect mean wait, worst wait, cars cleared and starvation events per run, and write three CSV files per run.
  • Report progress and an ETA to BatchRunPanel.

02One batch, one run

Why the warm-up. A run starts on an empty road. The first 120 s are thrown away (ResetRun at line 461), so every measurement starts from traffic that has reached a normal state. Note that the SODA counters inside AdaptiveController are not cleared at that point; see DataLogger's issues.

03The four scenarios

Rates are mean seconds between cars, per lane, as saved in the scene, which is what batch v5 ran. A and A2 come from one combined through-traffic rate split by a2Share; "closed" is a huge interval rather than zero, because the Poisson gap multiplies by it.

Measured

MorningPeak and MiddayNormal: Itim's detector run over the drone clips (MiddayNormal CB/CA added 10 Sep).

Assumed

EveningPeak and ABACEvent were never filmed. ABACEvent was rescaled on 18 Sep, after its old rates put Bx at v/c 9.6 and gridlocked 10 of 54 runs.

What if: the A2 share

Through traffic on the eastbound approach is split between the inner lane (A) and the outer lane shared with Ax (A2). Itim counted 3 of 56 through vehicles in the outer lane (5.4%), replacing an 18% that had been back-calculated from a blocking rate.

04Settings, and how they are protected

a2Share is corrected automatically on load, because a wrong share would make the batch and the test cases split traffic differently. repetitionsPerScenario only triggers a warning, because lowering it is a legitimate way to run a quick test.

05Progress and ETA

An earlier version divided elapsed time by runs started, so the estimate grew while the first run was still going. Now it uses runs actually finished, and before the first run finishes it uses the theory: 1,920 simulated seconds ÷ 10. EtaTest checks that the estimate only ever falls.
