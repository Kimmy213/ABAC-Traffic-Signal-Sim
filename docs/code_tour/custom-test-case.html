On this page

01Big picture

A window (press N) for building a test case during Play, without the Inspector and without recompiling. The result is an ordinary TestCase, so it runs through exactly the same path as T1-T13. There is no second code path to keep in step.

  • Scripted: either a total split by percentages, or a count per lane; cars a constant gap apart, or at random gaps from a range with a seed.
  • Poisson: a mean interval per lane, shown in veh/h as well, since field counts are quoted that way.
  • Driver mix, applied to every spawner. Run this now or Add to list.

02Splitting a total without losing cars

Rounding each lane's share separately can miss the total that was asked for. The code uses the largest-remainder method instead: round every lane down, then give the cars left over to the lanes with the largest fractions.

Try it: largest remainder

A port of ResolveCounts. Shares need not add to 100; they are normalised. Try 40 cars over three equal lanes: plain rounding gives 39, and the method gives 40.

03Turning the settings into a case

Random gaps are made as one burst per car, so CarSpawner needs no new mode. Each lane's draws come from its own generator, seeded with gapSeed × 7919 + StableHash(lane): the same seed always gives the same cars, and Unity's global Random is never touched.

The driver mix is written into every spawner and stays there after the case. If a custom run changes it, later runs in the same Play session use the new mix until Play is restarted.

04Every variable

Saved values are read from SampleScene.unity (GameController). The case being edited is held in private fields and starts from defaults every Play: 8 cars and 2 s per lane, Poisson 7 s, mix 25 / 60.
